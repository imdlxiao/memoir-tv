# 家庭影像库的目录与容量设计

作者：donglixiao

## 本机目录

```text
F:\家庭回忆库\
  原片\
    2026\
      2026-02\
      2026-05\
      2026-06\
      2026-09\
    日期待补\
  索引与缓存\
    catalog.json
    memories.json
    identities.json
    thumbnails\
    metadata\
  备份\
    迁移-20260921\
```

每段视频、每张照片保持独立原文件。按年／月组织，文件名保持原样；照片和视频可放在同一月份，网页根据媒体类型筛选。没有可信日期的文件归入「日期待补」，不根据备份时间猜日期。

以后新素材直接放进对应的月份目录；一时记不清日期的放到「日期待补」。网站支持子目录扫描。地点、人物、旅行、生日等交叉分类用标签和地点字段，一份原片可以属于多个主题，不为分类复制多份。

通常不需要继续细分到每天。某个月素材特别多时，可人工增加事件／导入批次子目录。目录分类用于管理、备份、定位原片；缩减读取与播放消耗由索引、缓存、分页、视频编码分别解决。不要将所有视频拼成一个大文件或放进压缩包作为在线素材库。

## 已实现的性能措施

- 首次发现素材时建立索引；正常页面轮询复用未变化目录的文件列表。新增、移出、改名触发所属目录重新枚举，而不是每个客户端反复遍历所有文件。
- 成员发生变化时，指纹未变的旧条目复用既有记录，仅为新增／变化的条目读取参数缓存。JSON 索引发布仍需要合并和写出整份索引，不是数据库级逐行更新。
- 每 60 秒的下一次访问核对文件属性，补查目录时间未变化的原地覆盖；管理页「刷新回忆库」会强制核对。目录不可用时保留已有索引，不误判为空库。
- 并发客户端的后台检查在服务端共享短时间窗口；索引和编辑文件未变时复用合并结果、序列化字节和 ETag。未变化返回 HTTP 304，不重复传输整个索引。
- 播放原片按 ID 查找，使用缓存字典；HTTP Range 只传所需字节，不把大型视频整段读入内存。
- 封面与拍摄参数按 ID、文件大小、修改时间缓存；正常浏览不重复解码原片或重新读取 EXIF。
- 带文件指纹的封面 URL 使用浏览器私有长期缓存，重复浏览不会反复下载同一封面；原片 URL 不套用这项长期缓存。
- 首页先渲染 12 条，封面延迟加载；未打开的原片不作为多个播放器同时加载。当前尚未实现虚拟列表，用户持续点「更多」仍会增加 DOM。
- `data_root` 可把索引与缓存放在独立位置，程序源码和原片目录分开。F 盘中只有「原片」是扫描入口，备份与封面不会被当作新回忆。

## 规模实测与边界

本机执行 `python scripts/benchmark_catalog.py --items 20000`，使用 2 万个空的合成素材文件，分布在 45 个目录：首次索引约 7.035 秒，未变化的检查中位数约 11.593 毫秒；完整索引约 7.02 MB，未变化响应体为 0 字节，并复用同一序列化缓存。此测试覆盖文件系统与索引开销，不是原片解码、网络带宽或电视实机测试；不同磁盘结果会不同。

首屏仍需下载一次完整 JSON，筛选和统计在浏览器进行。数量继续增长时，应根据实际首屏时间和内存升级为服务端查询、游标分页与 SQLite 索引，再做虚拟列表；不是把所有查询成本靠分文件夹解决。JSON 静态导出继续作为可移植发布格式保留。

原片码率高时，即使只有一个文件也可能在 Wi-Fi 上卡顿。下一阶段可为需要的素材生成 1080p H.264 播放副本，保留原片供下载；字幕、转码和多码率流不在本次迁移中自动执行，避免占用大量额外空间或降低唯一原片质量。

增量索引复测：在上述 2 万条模拟数据上，首次扫描约 9.047 秒、未变化检查约 11.453 毫秒，新增一条的索引更新约 989.923 毫秒（不含封面解码）。测量同时有迁移／浏览器测试运行，数字用于说明工作量边界，不作为固定性能承诺。

## 本次迁移与身份保留

本次从 `G:\dcim备份` 迁移 26 段视频，合计 96,221,843,960 字节（89.61 GiB）。先生成逐文件计划，复制时计算源 SHA-256，读取完整目标文件计算 SHA-256；全部校验后切换配置和索引，再清理已确认的源文件。

`identities.json` 保存新相对路径到旧回忆 ID 的一一映射。迁移保留原始文件时间，沿用封面／元数据缓存，因此标题、标签、坐标、收藏与浏览器播放进度仍指向原来的 ID。以后手动移动到新的相对路径仍可能改变 ID；有标注的素材应通过受控迁移更新映射，不要随意重命名已经整理好的目录。普通扫描不会因为修改了拍摄日期而擅自搬动原片。

备份至少保留原片、`memories.json`、`identities.json` 和本机配置；封面与 EXIF 缓存可重建。F 盘的「备份」目录仅保存本次迁移清单和小型记录快照，不能防范 F 盘硬件故障，完整灾备还需要另一块磁盘或独立存储。
