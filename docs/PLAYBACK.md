# 手机与电视流畅播放

作者：donglixiao

播放器默认选择已生成的流畅版，可通过「画质 → 原画」切回原文件。下载始终下载原片。还没有副本时先播放原画，点击「生成流畅版」后显示排队和生成进度；生成完成会保留当前进度、暂停状态和倍速切换。首次处理长视频需要等待，之后所有有权限的设备复用同一份缓存。

## 配置与资源占用

在本机 `config.local.json` 中配置：

```json
{
  "playback_encoder": "libx264",
  "playback_prewarm": false
}
```

默认软件编码器要求 FFmpeg 包含 libx264。也支持 `h264_amf`（AMD）、`h264_nvenc`（NVIDIA）、`h264_qsv`（Intel），需对应硬件与驱动；工具列出编码器并不保证硬件可用，应先验证实际转码。修改配置后重启服务。失败状态保留到服务重启，避免打开同一视频不断重试。

开启 `playback_prewarm` 会在服务启动后按文件大小从小到大准备已有视频。新视频可在播放器中按需生成。每次最多运行一个 FFmpeg，待处理队列上限 8 条；软件解码与滤镜限制线程，Windows 使用低于正常的进程优先级。后台生成仍会使用磁盘、CPU/GPU，首次大量准备时会比单纯播放占用更多资源。

副本为 H.264/AAC MP4，最长边不超过 1280、画面适合 1280×720 范围，保持比例、不放大，最高 30 fps；视频目标 2.2 Mbps、峰值目标 2.8 Mbps，音频 128 kbps。码率受编码器控制，不等于每个网络包的瞬时速度。MP4 使用 faststart，索引移到文件头便于开始播放。原片的画质、帧率、音轨和元数据保持不变；需要原始 HDR、多音轨或高帧率时选择原画。

缓存位于 `data_root/playback`，和家庭索引一样不能提交 Git。按原片路径、大小和修改时间生成指纹，原片变更后旧副本不会继续提供。原片移出后副本也不能访问。缓存总预算 20 GiB、单份上限 4 GiB，并为磁盘保留 1 GiB；达到限制会明确提示，继续允许播放原画。需要释放空间时先停止服务，再删除该专用目录内的生成副本；它们可重新生成，切勿删除原片目录。异常断电遗留的 `.part.mp4` 也在此专用缓存目录内，不能作为成品访问。

## 权限与诊断

状态查询、生成请求、MP4 的 GET/HEAD/Range 都验证当前用户权限。流畅版继承原片的可见范围和访问日志，持续传输时仍定期检查会话撤销。文件不放进公开静态目录；公开静态导出仍使用原片，不启动转码接口。

「播放诊断」显示当前播放点后已缓冲的秒数、等待次数、浏览器报告的丢帧数、原片平均码率。它不上传诊断或家庭素材。缓冲接近 0 时反复停顿说明数据供给不足；缓冲充足却明显跳帧则需检查设备解码能力。单凭该面板不能区分 Wi-Fi、磁盘和网络路径的瓶颈，也不是带宽测速结果。

验证：`python -m unittest discover -s tests -v`，以及 `python tests/browser_playback.py`。界面测试仅使用临时目录和合成视频，覆盖现代/兼容模式、手机尺寸、画质切换、进度恢复与转码失败提示。
