# 电视浏览与故障定位

作者：donglixiao

## 地址打不开时

2026-09-21 在用户 MuMu（Android 12 / WebView 110.0.5481.154.1）复现：`.local` 地址返回 `ERROR_HOST_LOOKUP (-2) / net::ERR_NAME_NOT_RESOLVED`，改用同一电脑的局域网 IP 后登录页返回 HTTP 200。这个结果确认的是 MuMu 的域名解析失败；目标电视的具体错误应通过新版浏览器错误页确认，不能仅凭相似截图断言。

百度使用公共 DNS，能打开百度不代表设备能解析局域网 `.local`。mDNS 还受 Android 版本、厂商系统及虚拟网络组播支持影响。遇到此错误，可用 `http://素材电脑IP:8765/`；要保持 IP 长期不变，应在路由器设置 DHCP 地址保留。网站或浏览器更新不会自动修改路由器。

配套 TvBrowser 新版错误页显示系统错误码、原始原因、失败地址和 Android/WebView 版本，提供 DNS/TCP 连接诊断。工具栏「地址」可修改网址，勾选「同时更新首页收藏地址」后持久保存。没有把当前电脑 IP 硬编码为所有用户的默认值。

| 结果 | 含义与检查方向 |
| --- | --- |
| `ERROR_HOST_LOOKUP / ERR_NAME_NOT_RESOLVED` | 名称解析失败；用局域网 IP 对照验证 |
| `ERROR_CONNECT / ERR_CONNECTION_REFUSED` | 无法连接目标端口；检查服务、端口、监听地址、防火墙 |
| `ERROR_TIMEOUT` | 连接超时；检查路由、客户端隔离、服务响应 |
| `HTTP 401 / 403` | 已连接服务器，检查登录与内容权限 |
| `SSL_CERTIFICATE_ERROR` | 证书或设备时间异常；不会绕过证书校验 |
| 页面启动失败提示 | 网页已经到达，检查提示中的脚本或兼容资源错误 |

## 遥控操作

- TvBrowser、Android TV、SmartTV 等标识触发自动大屏与导航；其他浏览器可手动进入「客厅放映室」。
- 方向键按屏幕位置选择控件；确认键使用浏览器原生点击，保留输入法和媒体用户手势。
- 输入框上下换项、左右移动光标；下拉框左右换值、上下离开。输入法打开时先用完成或返回关闭键盘。
- 弹窗内不会跳到后面的页面；返回依次退出全屏、关闭弹窗、退出大屏模式，再交还浏览器历史。
- 菜单键回到 TvBrowser 工具栏；工具栏向下或「浏览网页」返回页面。
- 播放器有暂停、前后 10 秒、速度、循环、连续播放、上一段／下一段按钮。媒体播放、暂停和快进键也可用。
- 文件夹同步不会把正在选择的卡片焦点重置到页面开头；播放和编辑期间继续暂缓列表刷新。

## 大屏播放与全屏

电视放映室使用整个网页视口显示视频，标题和控制栏覆盖在画面上，不再挤占视频高度。视频正常播放约 4 秒后自动隐藏控制栏；按确认或方向键首先唤醒操作栏，随后确认操作。暂停时控制栏保持显示。进度条获得焦点后左右快进／后退 10 秒。

倍速、循环、连播、画质、播放诊断、原片信息收进「播放设置」。设置打开时遥控焦点留在面板内，返回依次关闭设置、退出系统全屏、关闭放映室。配套 TvBrowser 需要安装包含全屏遥控修复的新版 APK；旧安装包的原生全屏视图可能吞掉方向键和确认键，或者先退出全屏。刷新网站可以更新播放布局，但不能更新 Android 应用中的按键转发。

默认「完整显示」保持原比例，4:3 或竖屏素材可能留有左右黑边，这是保留完整内容的结果。选择「播放设置 → 画面比例 → 铺满屏幕（裁剪）」可铺满显示区域，边缘画面会被裁掉。全屏按钮进入浏览器全屏并使用同样的悬浮布局；如果内核拒绝全屏，仍铺满网页可用区域并明确提示。切换下一段复用全屏元素，不会因为重建播放器意外退出全屏。

`python tests/browser_cinema.py` 使用合成素材检查不同电视视口、控制栏隐藏／唤醒、设置焦点、画面比例、原生全屏及拒绝全屏后的回退。`player.css` 单独承载播放布局，兼容回退不依赖旧 WebView 的 `vh`、`dvh` 或 flex gap。

## 兼容构建

运行网站依旧只需 Python 标准库，无 Node 或编译器依赖。开发者修改 `web/js/` 后需更新已提交的兼容包：

```shell
python scripts/build_web.py --download
python scripts/build_web.py --check
```

首次构建下载固定版本 esbuild 0.25.10 的独立可执行文件并核对 npm SHA-512 完整性，缓存于忽略的 `.local/tools/`。后续构建不需要 `--download`。生成 `web/compat/` 的三个入口包，语法目标为 Chrome 58；`boot.js` 补齐使用到的 `Object.fromEntries` 和 `replaceChildren`。CSS 提供视口高度、媒体比例、对话框宽度和间距兼容。目标语法版本不等于所有该版本设备均已验收。

源码／产物指纹在 CI 核对，避免只修改现代脚本、遗漏旧电视版本。现代浏览器继续加载 ES 模块；`?compat=1` 可在开发时强制测试兼容入口。静态导出包含这些资源，嵌套目录仍可使用。

## 验证

电视嵌入式 WebView 实测还会把 CSS 视口高度算成 0，导致弹窗仅剩边框、视频尺寸为零；在 WebView 69 和 MuMu WebView 110 均复现。电视与旧内核入口使用实际 `innerHeight` 同步高度变量，弹窗与媒体据此布局，并随窗口尺寸更新；仪器测试同时断言弹窗、视频的实际尺寸，并用合成素材截图检查画面。

`python tests/browser_tv.py` 使用临时家庭库和合成 MP4，覆盖现代／兼容登录、方向导航、后台刷新焦点、播放控制、下拉框、弹窗返回与管理页；不访问真实家庭记录。

配套 Android 仓库有真实 WebView 仪器测试。联调时先运行 `python tests/tv_fixture.py --port 18765`，对指定测试设备执行 `adb reverse tcp:18765 tcp:18765`，再向 Android 测试传入 `memoirUrl=http://127.0.0.1:18765/`。服务只监听回环地址，结束后停止临时服务。测试账号 `test-owner` / `Fixture-Password-2026` 只存在于此临时库。

本轮验证包含 Android 8 / WebView 69.0.3497.100 与用户 MuMu Android 12 / WebView 110；并完成原有电脑、手机、地图、权限回归。电视硬件解码、厂商遥控键码与输入法仍以目标电视安装验证为准。
